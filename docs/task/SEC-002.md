## Description

`crates/gated-protocol-http/src/api/db_query.rs:195` 的 `is_readonly_sql` 只做注释剥离 + 关键字前缀匹配。该策略对以下场景存在绕过：

- 复合语句：`SELECT 1; UPDATE t SET x=1;`（取决于驱动与服务端 `multi_statements` 配置）。
- 可写 CTE：`WITH w AS (DELETE FROM t RETURNING *) SELECT * FROM w;`（Postgres）。
- 服务端函数：`SELECT pg_read_server_files(...)` / `SELECT sys_exec(...)` / `xp_cmdshell`。
- 大小写 / 空白 / Unicode 变体。

验收标准：
- 用 `sqlparser` 按 MySQL / Postgres dialect 解析，白名单 `Query` / `Explain` / `ShowVariable` / `ShowColumns` 等只读节点。
- 对函数调用维护危险函数黑名单（可按 backend 区分）。
- 所有驱动层面显式拒绝多语句（sqlx `execute_many` 不启用，或在参数层拒绝 `;` 之后的非空字符）。
- 补单元测试覆盖上述绕过用例；`tests/db/sql-console.test.ts`（TEST-003）补集成级用例。

## ActiveForm

替换只读 SQL 校验为 AST 级白名单

## Notes

评估 `sqlparser` crate 对二进制体积影响；若过大考虑 feature gate。保留当前的 prefix 快速路径作为 pre-check。

### 方案（Phase 2 proposal）

选手写 tokenizer 而非引入 `sqlparser`：

- sqlparser 体积 + 依赖复杂度（MySQL / Postgres 双 dialect，版本升级频繁）。
- 我们需要的语义是"不得执行任何修改"，而不是完整的 AST 分析，手写字符串分词器（剥离注释 / 字符串 / dollar-quote）+ 关键字黑名单 + 危险函数黑名单足够覆盖目标攻击面。
- 单元测试覆盖率高（表驱动 case），比 AST 更容易审计。

新增 `crates/gated-protocol-http/src/api/sql_validation.rs`：

- `fn strip_comments_and_strings(sql) -> String`：剥离 `--` 行注释、`/* */` 块注释、`'...'` / `"..."` / MySQL `` `...` `` 标识符引号、Postgres `$tag$...$tag$` dollar-quote 字符串。
- `fn tokenize(stripped) -> Vec<String>`：按非字母数字分割，保留 UPPER-case 纯字母 token。
- `pub fn validate_readonly_sql(sql) -> Result<(), ReadonlyViolation>`：
  - 检查剥离后的语句是否为多段（按 `;` split，非空段 > 1 → `MultipleStatements`）。
  - 第一个 token 必须是 SELECT / SHOW / EXPLAIN / DESCRIBE / DESC / WITH，否则 `NotReadOnly`。
  - 任一 token 命中写关键字集合（INSERT/UPDATE/DELETE/DROP/TRUNCATE/ALTER/CREATE/MERGE/REPLACE/GRANT/REVOKE/CALL/COPY/VACUUM/LOCK）→ `WriteKeyword`。
  - 任一 token 命中危险函数黑名单（pg_read_server_files, pg_write_server_files, pg_read_binary_file, lo_import, lo_export, xp_cmdshell, sys_exec, load_file, sleep, pg_sleep, benchmark）→ `DangerousFunction`。
- 单元测试 20+ 用例覆盖：基本 SELECT、WITH CTE、复合语句、注释包裹 UPDATE、`COPY FROM PROGRAM`、`SELECT pg_read_server_files('/etc/passwd')`、大小写变体、dollar-quote 包裹的 fake UPDATE。
- `db_query.rs` 替换 `is_readonly_sql` 调用为 `validate_readonly_sql`；`readonly` 拒绝响应附带具体违规原因（`ReadonlyViolation::to_response_message()`）以便前端展示。

### 风险

- 手写分词器覆盖度依赖测试全面性；引入 DANGEROUS_FUNCS / WRITE_KEYWORDS 黑名单意味着未来新出现的危险函数需要手动补。
- 黑名单关键字可能误伤合法查询，例如列名叫 `update`（包含在 `"` 或 `` ` `` 内会被剥离；但如果裸出现则误判）。通过剥离反引号 / 双引号标识符的内容来缓解。
- `sleep` / `pg_sleep` 在黑名单里：`SELECT pg_sleep(0.1)` 是合法测试场景但会被拒绝；对 DB Console 用户可以容忍，有 superuser 权限的 DBA 可走其他通道。

### 实施结果

- 新增 `crates/gated-protocol-http/src/api/sql_validation.rs`（约 330 行，含 10 个单元测试）。
- `db_query.rs` 的 `is_readonly_sql` 被删除，readonly 分支改为调用 `validate_readonly_sql`，拒绝时返回 `ReadonlyViolation::Display` 文案并打 `tracing::warn!` 审计日志。
- `cargo check --workspace --all-features` clean；`cargo cranky -p gated-protocol-http` 与主干保持一致（仅保留 DB Phase 1 pre-existing `db_terminal.rs:256` 的 indexing-slicing 错误，与本任务无关）。
- 10 个单元测试全通过：基本 SELECT、写前缀、复合语句、可写 CTE、危险函数、注释包裹写语句、字符串/反引号/dollar-quote 包裹、COPY FROM PROGRAM、空/纯注释、schema-qualified 标识符。
- 集成级验证留给 TEST-003。
