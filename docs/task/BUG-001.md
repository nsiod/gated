# BUG-001 Fix ticket creation datetime submission

- **status**: completed
- **priority**: P1
- **owner**: Codex
- **createdAt**: 2026-04-23 04:31

## Description

Creating a ticket from `/ui/admin/config/tickets/new` can fail with HTTP 400 when the form submits an expiry value from the browser `datetime-local` input. The backend `POST /tickets` request schema expects `expiry` as an RFC3339 `date-time`.

Acceptance criteria:

- Ticket creation succeeds when required fields are provided without expiry.
- Ticket creation succeeds when an expiry is selected in the UI.
- Invalid numeric use counts are rejected before submission.

## ActiveForm

Fixing ticket creation datetime submission.

## Notes

- Investigation found `create-ticket.tsx` submits `datetime-local` values directly, while `CreateTicketRequest.expiry` is generated from OpenAPI as `format: date-time`.
- Implemented `create-ticket-request.ts` to build the API payload from validated form values. Expiry values are serialized with `Date#toISOString()` before `POST /tickets`, and `number_of_uses` now accepts only positive integer strings.
- Added focused Vitest coverage for blank optional fields and RFC3339 expiry serialization.
- Verification: `pnpm run check`, `pnpm exec vitest run src/features/admin/pages/config/create-ticket.test.ts`, `pnpm run test`, and focused ESLint all pass. `bun`/`bunx` were not installed in this environment, so `pnpm` was used against the existing `node_modules`.
