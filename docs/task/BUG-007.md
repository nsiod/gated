# BUG-007 Record MySQL and Postgres gateway terminal sessions

- **status**: completed
- **priority**: P1
- **owner**: Codex
- **createdAt**: 2026-04-23 16:05

## Description

The gateway currently records SSH terminal sessions, but the MySQL and
Postgres Web terminal routes do not create terminal recordings. As a
result, DB CLI sessions do not appear in the admin session recordings
list and cannot be replayed from `/ui/admin/recordings/:id`.

Acceptance criteria:

- MySQL terminal sessions started from the gateway create terminal
  recordings when session recording is enabled.
- Postgres terminal sessions started from the gateway create terminal
  recordings when session recording is enabled.
- Admin recording detail pages show meaningful type labels and metadata
  for the new DB terminal recordings instead of `Unknown type`.
- Focused tests cover the new recording path or metadata handling
  introduced by the change.

## ActiveForm

Investigating and preparing DB terminal recording support for MySQL and
Postgres gateway sessions.

## Notes

- Investigation traced SSH web terminal recording creation to
  `crates/gated-protocol-http/src/api/ssh_terminal.rs`, which starts a
  `TerminalRecorder` immediately after the session is established.
- `crates/gated-protocol-http/src/api/db_terminal.rs` registers the
  session and bridges WebSocket traffic to a PTY running `mysql` or
  `psql`, but it never starts a recorder and never forwards PTY traffic
  into the recordings subsystem.
- Admin session recording lists are backed directly by the
  `recordings` table, so DB terminal sessions cannot appear until the
  backend writes recording rows.
- Frontend recording metadata parsing in
  `crates/gated-web/src/shared/lib/recordings.ts` only recognizes
  Kubernetes and SSH metadata types today.
- Implemented `TerminalRecorder` startup for DB terminal sessions and
  wired PTY input, output, and resize events into the shared terminal
  recording format.
- Added MySQL/Postgres terminal metadata labels and focused Vitest
  coverage for frontend recording metadata mapping.
- Verification:
  `cargo fmt --all`,
  `cargo check -p gated-protocol-http`,
  `pnpm exec vitest run src/shared/lib/recordings.test.ts`,
  and `pnpm exec tsc --noEmit -p tsconfig.json` in
  `crates/gated-web`.
