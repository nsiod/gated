# OBS-001 Prometheus /metrics 端点

- **status**: completed
- **priority**: P2
- **owner**: claude-code
- **createdAt**: 2026-04-18 20:55
- **completedAt**: 2026-04-19 06:20

## Description

项目目前没有 Prometheus / metrics 暴露，运维无法观测连接数、鉴权结果、SQL 查询速率等核心指标。

验收标准：
- 引入 `metrics` + `metrics-exporter-prometheus` crate。
- 新增 HTTP 端点（例：`gated.metrics.listen` 配置项，默认 `127.0.0.1:9090`，默认关闭或仅 loopback），与业务端口分离以避免暴露面扩散。
- 核心指标：
  - `gated_sessions_active{protocol}`
  - `gated_auth_attempts_total{result,method}`
  - `gated_db_query_total{target,result}`
  - `gated_db_query_duration_seconds{target}`（histogram）
  - `gated_rate_limit_rejected_total{endpoint}`
  - `gated_config_reload_total`
- 为所有关键路径埋点；配 `docs/ops/metrics.md` 指标字典。

## ActiveForm

增加 Prometheus metrics exporter

## Dependencies

- **blocked by**: PERF-002
- **blocks**: OBS-002

## Notes

默认仅绑定 loopback，避免公网暴露内部计数器；对外暴露需显式配置并配合 TLS。

## Proposal

### 依赖
- workspace 新增：`metrics = "0.24"` 与 `metrics-exporter-prometheus = "0.17"`（`default-features = false` + `http-listener` 关闭，我们自己起 HTTP 端点方便 graceful shutdown）。
- 仅 `gated-core`（安装 recorder + 轻量包装）和 `gated`（spawn 监听器）依赖这两个新 crate。埋点点通过 `metrics::counter!` / `histogram!` / `gauge!` 宏调用，这些宏在未安装 recorder 时是 no-op，所以 `enable = false` 的场景零开销、零行为差异。

### 配置
在 `crates/gated-common/src/config/mod.rs` 的 `GatedConfigStore` 中加：
```rust
#[serde(default)]
pub metrics: MetricsConfig,
```
同文件内定义：
```rust
pub struct MetricsConfig {
    pub enable: bool,            // 默认 false
    pub listen: ListenEndpoint,  // 默认 127.0.0.1:9090
}
```
与现有 `HttpConfig` / `SshConfig` 同风格。JsonSchema 由 derive 自动带上。

### Services 注入
在 `Services` 中加：
```rust
pub metrics: Option<Arc<PrometheusHandle>>,
```
启动时如果 `metrics.enable = true`，在 `Services::new()` 之前调用 `PrometheusBuilder::install_recorder()` 把全局 recorder 装好并保存 `PrometheusHandle`。Option<None> 的情况下埋点宏依然 no-op，抓取端点返回 503。

### 监听器
`crates/gated/src/commands/run.rs` 现有 `FuturesUnordered` 里新加一个 future：用 poem 起一个最小服务，路由只有 `GET /metrics` → `handle.render()`。没有 TLS（默认仅 loopback），也不走 gated 自己的鉴权栈（metrics 端口按约定只给内网 Prometheus 抓）。

### 埋点（本 PR 范围）
- `gated_sessions_active{protocol}`：`gated_core::State::register_session` 增、`remove_session` 减。protocol 来自已有的 `ProtocolName` 参数。
- `gated_auth_attempts_total{result, method}`：`crates/gated-protocol-http/src/api/auth.rs` 现有五条 audit 事件就已经覆盖到 login / otp / logout × 成功/失败；每条事件旁加一次 `counter!`，label 直接沿用现有的 `result` + `method` 语义。
- `gated_db_query_total{target, result}` + `gated_db_query_duration_seconds{target}`：`db_query.rs` 的成功（行 847 前）与失败（行 860 前）分支。duration 直接复用已计算的 `elapsed`。
- `gated_rate_limit_rejected_total{endpoint}`：`db_query.rs` 的 `sql_console_rate_limit_exceeded` 附近加 `endpoint="sql_console"`；`db_terminal.rs` 的对应分支加 `endpoint="db_terminal"`。
- `gated_config_reload_total`：`crates/gated/src/commands/run.rs` 的 `reload_event.recv()` 成功分支。

**不在本 PR 范围**：
- 原生 MySQL / Postgres / SSH / Kubernetes 协议代理的 per-query / per-connection 指标——这些需要分别到 `gated-protocol-*` 各 crate，范围太散，可走 OBS-001 后续或 PERF-002 顺手做。
- `gated_db_pool_size / _idle`——等 PERF-002 把 pool registry 挪进 Services 后再做，避免跟本任务耦合。

### 风险 / 验证
- 启动时如果 `install_recorder` 失败（比如被别的 crate 预装了 recorder），记为 `error!` 并让 gated 继续跑，`metrics.enable` 视为 false。不让 metrics 的故障阻塞网关启动。
- Scrape 路径不应共享主业务锁。这里埋点用 metrics 宏，写入的是 metrics 自己的内部 atomic 结构，不涉及 `Services::db` / `state` 锁，符合调研报告的第 7 条注意事项。
- 新增 `docs/ops/metrics.md` 列出每个指标的名字、类型、标签和采集点；与 `docs/ops/logging.md` 并列。

### 端口
默认 `127.0.0.1:9090`。与已有网关端口（8443 / 2222 / 3306 / 5432 / 8001）无冲突。若 9090 被占用，管理员在 YAML 里显式改 `metrics.listen`。

## Completion

- Workspace 新增 `metrics = "0.24"` + `metrics-exporter-prometheus = "0.17"`（`default-features = false`，不引入 hyper listener，自己用 poem 起最小端点）。
- `gated_common::MetricsConfig { enable, listen }` 新字段，默认 `enable = false` / `listen = 127.0.0.1:9090`。
- `gated_core::metrics` 模块封装 `install_recorder`（含 `describe_metrics`：每个指标家族一条 `# HELP` 描述 + 无标签的 `gated_config_reload_total` 零初始化）。
- `Services::new` 签名多了一个 `metrics: Option<Arc<MetricsHandle>>` 参数；`create_user` / `recover_access` / `run` 三个 CLI 入口都传。
- `run.rs` 在 `FuturesUnordered` 里注册一个 poem `/metrics` 端点（`Content-Type: text/plain; version=0.0.4`），仅在 `enable = true` 且 `install_recorder` 成功时挂入。
- 埋点：
  - `gated_sessions_active{protocol}`：`State::register_session` 增、`remove_session` 减；`protocol` 直接沿用 `ProtocolName`（`&'static str`），无克隆。
  - `gated_auth_attempts_total{result, method}`：`auth.rs` password 与 OTP 两个 handler 按 `AuthResult::{Accepted, Rejected, Need}` 三臂分支——`Need(...)` 多因素未完成不计为 rejected。`UserNotFound` 早返回路径也计。
  - `gated_db_query_total{target, result}` + `gated_db_query_duration_seconds{target}`：`db_query.rs` 成功 / 失败两侧。
  - `gated_rate_limit_rejected_total{endpoint}`：`sql_console`（`db_query.rs`）+ `db_terminal`（`db_terminal.rs`）。
  - `gated_config_reload_total`：`watch_config_and_reload`。
- `docs/ops/metrics.md`：指标字典 + 暂不覆盖项（DB pool 指标阻塞在 PERF-002；wire-protocol 级连接计数留给 follow-up）+ 命名约定 + 抓取示例。
- `tests/misc/metrics.test.ts`：两段 smoke：disabled 时端口不 listen；enabled 时 `GET /metrics` 返回 `# TYPE gated_` + 触发一次 `gated_auth_attempts_total`。

**Out of scope（为不让本 PR 失控跳过）**：
- `gated_db_pool_size{target}` / `gated_db_pool_idle{target}`——需要 PERF-002 先把 pool registry 挪进 `Services`。
- 原生 MySQL / Postgres / SSH / Kubernetes 协议代理的 per-connection 指标——分散到四个 crate，作为 follow-up（可能合并进一个 OBS-001.b）。
- Feature-gate `metrics-exporter-prometheus`——二进制里多了 `quanta` / `sketches-ddsketch` / `metrics-util` / `ahash` / `crossbeam-epoch` / `rand_xoshiro` 这一串，但量级 kB 级，暂不拆 feature。需要时再加。

**Review（/simplify fallback）发现并修复**：
- auth.rs 原先把 `AuthResult::Need(...)` 计入 rejected → 会让登录成功率看起来只有一半。改成三臂 match。
- `SessionState.protocol` 从 `String` 改成 `&'static str`，register / remove 各省一次克隆。
- `/metrics` 加显式 `text/plain; version=0.0.4`，兼容 Grafana Agent / vmagent。
