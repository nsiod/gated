# BUG-002 Fix recording detail mobile overflow

- **status**: completed
- **priority**: P1
- **owner**: Codex
- **createdAt**: 2026-04-23 13:44

## Description

The admin recording detail page at `/ui/admin/recordings/:id` can overflow horizontally on narrow screens. The terminal playback area is wider than the viewport, so the page width exceeds the device width instead of containing the player within the available space.

Acceptance criteria:

- The recording detail page stays within the viewport width on mobile-sized screens.
- Terminal recordings remain playable after the layout fix.
- The fix is limited to the recording detail page and player layout.

## ActiveForm

Diagnosing and fixing recording detail page overflow on narrow screens.

## Dependencies

- **blocked by**: (none)
- **blocks**: (none)

## Notes

- Investigation found the player is only rendered for terminal recordings in `features/admin/pages/recording.tsx`.
- `TerminalPlayer` initializes xterm with the recorded column count and does not currently apply width constraints such as `min-w-0`, `max-w-full`, or horizontal containment on its viewport wrapper.
- The controls row also uses a single-line flex layout, which may need wrapping on very narrow screens depending on the final fix.
- Implemented container-constrained terminal fitting in `TerminalPlayer`: call `fit.fit()` after mount and on container resize via `ResizeObserver`, and added `min-w-0` / `max-w-full` constraints so the player respects the card width.
- The recording player controls now allow wrapping on narrow screens, preventing the slider and speed selector from forcing page-level overflow.
- Added page-level `min-w-0` / `max-w-full` constraints to the recording player card in `recording.tsx` so the route layout can shrink correctly.
- Verification: `pnpm exec eslint src/shared/components/terminal-player.tsx src/features/admin/pages/recording.tsx` and `pnpm exec tsc --noEmit -p tsconfig.json` in `crates/gated-web` both pass.
