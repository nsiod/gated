## Description

`gated healthcheck` 当前仅做 TCP 级别探活，无法覆盖 DB / 迁移 / TLS 证书 / 鉴权后端是否正常，导致 Kubernetes 探针无法区分 "进程活着但服务不可用" 的场景。

验收标准：
- 新增 `gated healthcheck --deep` 模式：
  - DB 连接 + 迁移版本比对。
  - DB 可读可写探测（幂等 no-op 事务）。
  - TLS 证书有效期检测（到期 < 7 天 WARN，过期 FAIL）。
  - LDAP / SSO 可达性（按启用项，支持 `--skip lookups`）。
- 输出 JSON（`{ status, checks: [{name, status, message}], generated_at }`）。
- 同时提供 `/healthz`（liveness：always 200）与 `/readyz`（readiness：走 deep check）HTTP 端点；绑定到 metrics 端口。
- 文档：`docs/ops/healthcheck.md`。

## Completion

- 新增 `gated-core::healthcheck` 模块：`deep_check(&DatabaseConnection, &GatedConfig, &Path, DeepHealthOptions)` 返回 `DeepHealthReport { status, generated_at, checks }`，三个 DB 探针通过 `tokio::join!` 并发跑。
- 新增 `gated-core::db::open_db_connection`：不跑 migrations 的 DB 连接打开函数，供 CLI deep check 用，避免「连接时就帮你 migrate 了，然后再报告 migrations 都 ok」的假阳性。
- 新增 `gated healthcheck --deep [--skip-lookups]` CLI 子命令参数；输出 pretty JSON；fail 时 `std::process::exit(1)` 不带 anyhow backtrace，方便 Docker HEALTHCHECK 使用。原有无参模式（basic HTTP ping）保留。
- 新增 `/healthz`（静态 200）+ `/readyz`（跑 deep_check，skip_lookups=true，外层 1500ms timeout guard）HTTP 端点，与 `/metrics` 共用 metrics listener（`run_observability_server`）。`/readyz` fail → HTTP 503，否则 200。
- 检查列表：
  - `db.ping`：`SELECT 1` round-trip，700ms timeout。
  - `db.migrations`：`Migrator::get_pending_migrations`，pending 非空 → fail。
  - `db.tx_roundtrip`：`BEGIN; COMMIT;`——只验证连接还能说 tx 协议，不是真实 write 测试（doc 里写清楚了）。
  - `tls.cert`：解析 `http.certificate` PEM，`not_after` 距今 < 7 天 → warn，已过期/文件缺失/空字段 → fail。HTTPS 关闭时直接 ok。
  - `ldap.reachability` / `sso.reachability`：bind/discovery probe 未实现，报 `warn`（而不是 ok）以免 dashboard 把"未实现"当健康。`--skip-lookups` 会把这两行从报告里去掉。
- `docs/ops/healthcheck.md`：三层健康信号（基础 CLI / 深度 CLI / HTTP probe）对比表、报告 JSON 示例、每个 check 的语义表、K8s probe 样例、Docker HEALTHCHECK 样例，以及「为什么不给 probe 单开一个端口」的说明。
- Smoke test `tests/misc/healthcheck.test.ts`：断言 `/healthz` 返回 200 + `"ok"`；`/readyz` 返回合法 JSON 报告，含四条本地 check（skip_lookups 时 LDAP/SSO 不出现），每条状态都是 ok。

**Review（/simplify fallback）发现并修复**：
- 原 CLI path 调 `Services::new` 会自动跑 migrations，让 `db.migrations` 永远 green——拆出 `open_db_connection` 走非 migrating 路径。
- `/readyz` 3 个 DB 探针原本串行、每个 3–5s，最坏 11s，远超 K8s 1s 默认 timeout——改成 `tokio::join!` 并发 + 外层 1500ms guard + 单探针 timeout 降到 700ms。
- LDAP/SSO 原来 stub 返回 ok → 改返回 warn，防止 "not implemented" 被当"健康"。
- CLI fail 时原本 `anyhow::bail!` 会打印栈回溯 → 改成 `std::process::exit(1)`，Docker HEALTHCHECK 只要 exit code，JSON 已经够了。
- `db.rw` → `db.tx_roundtrip` 重命名并 doc 说明它不是真实 write probe，避免虚假安心。
