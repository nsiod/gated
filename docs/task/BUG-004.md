# BUG-004 Fix admin sessions target search

- **status**: completed
- **priority**: P1
- **owner**: Codex
- **createdAt**: 2026-04-23 15:00

## Description

The admin sessions page at `/ui/admin` does not return rows when the
search input matches the session target name. Searching by fields such
as username still works, but searching for a visible target label like
`Target` does not.

Acceptance criteria:

- Searching on `/ui/admin` matches visible target names in the Target
  column.
- Existing search behavior for username, protocol, started time, and
  status remains unchanged.
- The fix stays limited to the sessions list search path.

## ActiveForm

Investigating and fixing admin sessions target-name search in the
shared table search flow.

## Dependencies

- **blocked by**: (none)
- **blocks**: (none)

## Notes

- Investigation traced the page to
  `crates/gated-web/src/features/admin/pages/sessions.tsx`, which uses
  the shared `DataTable` global filter locally rather than a backend
  `?search=` query.
- The sessions Target column renders `row.original.target?.name` in its
  cell, but did not expose that value through `accessorKey` or
  `accessorFn`, so TanStack Table global filtering could not match it.
- Implemented `accessorFn: row => row.target?.name ?? ''` on the
  sessions Target column while leaving the existing cell rendering
  unchanged.
- Added `crates/gated-web/src/features/admin/pages/sessions.test.tsx`
  to verify that entering a target-name search term filters the list to
  the matching row.
- Verification: `pnpm exec vitest run
  src/features/admin/pages/sessions.test.tsx`, `pnpm exec eslint
  src/features/admin/pages/sessions.tsx
  src/features/admin/pages/sessions.test.tsx`, and `pnpm exec tsc
  --noEmit -p tsconfig.json` in `crates/gated-web` all pass.
